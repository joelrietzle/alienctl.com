Problem

AI-agent PRs arrive with too much uncertainty.

Reviewers are asked to judge code after the fact, often without a clear record of what the agent changed, which commands ran, which evidence is missing, or whether sensitive surfaces need approval before review starts.

The Rule

No valid receipt, no AI-agent PR review.

alienctl turns the first decision into a local control point: may this AI-agent change begin human review, or must it be fixed, verified, approved, or reconstructed first?

How It Works

A local gate around the repo session.

  1. Observe the AI-agent repo session locally.
  2. Run local receipt-policy checks after the work stops.
  3. Generate a reviewer-ready workflow decision.
  4. Archive receipt evidence for later audit or incident reconstruction.

What A Receipt Answers

Before review, the packet should answer the obvious questions.

What changed?

Observed files, session attribution, and baseline quality.

What evidence exists?

Declared verification, receipt status, policy context, and archive paths.

What blocks review?

Failed checks, missing evidence, sensitive-surface approval gaps, or unclear attribution.

What is not proven?

No claim of code correctness, production safety, compliance, or ROI.

Local/BYOC Trust Boundary

Bring your own repo, policy, commands, and archive.

The current pilot shape is local and buyer-controlled. alienctl does not need a hosted dashboard, stored credentials, third-party analytics, or provider mutation to validate the workflow decision.

Two-Week One-Repo Pilot

Test the rule on one real AI-agent workflow.

A design-partner pilot names one repo, one owner, the verification commands, sensitive surfaces, local archive path, and the reviewer decision rule. The goal is to learn whether the receipt gate changes review behavior or reconstructability.

Non-Claims

The receipt is evidence, not a magic approval stamp.

  • alienctl does not prove code correctness.
  • alienctl does not prove production safety.
  • alienctl does not claim compliance or legal assurance.
  • alienctl does not claim ROI or cost savings.
  • alienctl does not add hosted behavior, payment custody, SDKs, or product UI.
  • alienctl does not claim mature enterprise platform readiness.
